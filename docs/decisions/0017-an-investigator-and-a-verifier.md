# 0017: An investigator and a verifier, a coordinator in code, and a person's approval

## Context
The engine decides what rules can decide and abstains on the rest; people work the queue. Some of what reaches people
is reading a document closely: an authority that grants the vote "subject to the approval of the board" and, two lines
down, records the approval; a passage that contradicts the field the rules read; a document of another process
standing in for this one's. A model can do that reading. The question is how to let one do it without letting it
decide anything, and how to know whether it helps.

## Decision
- **Two agents, two contexts** (`testamur.investigate`). The *investigator* reads the claim's evidence with read-only
  tools and answers with an evidence packet: findings, each with citations (document, page, words copied from it). The
  *verifier*, in a separate context with its own tools (it also sees a document's history across processes and how a
  document arrived), checks each finding against the documents and reports what the investigator missed. It sees the
  findings, not the investigator's conversation, so it checks evidence rather than reasoning.
- **Typed contracts** (Pydantic): agents answer only in the contract's shape, constrained during decoding (llama.cpp
  compiles the JSON schema into a grammar) and validated again after. Each turn carries a short note for the trace;
  no hidden reasoning is asked for or kept.
- **A coordinator in code.** Every identifier an agent returns is untrusted: a citation stands only if it names this
  claim's document and a real page and its words are on that page. The coordinator reconciles the agents with each
  other and with the rules: the agents may propose a verdict only for a check the rules could not decide; an agent
  disputing a rule's verdict, or the two agents disagreeing, sends the question to a person. It alone creates
  proposals, bound to the evidence (ADR 0014), idempotent per run.
- **Scoped tools.** A gateway runs every call in the run's tenant session, within the claim's evidence (any other
  document id is refused), within the role's tools and a call budget; documents that address automated readers are
  withheld. Every call, refused ones included, is a trace event.
- **Bounded.** Steps, tokens and a deadline per agent; up to two invalid answers sent back with the validation error;
  cancellation between steps. An agent that runs out of budget stops, and the claim goes to a person.
- **Durable** (LangGraph, checkpoints in SQLite beside the store). A crash during agent work resumes at the step it was
  on; a restart during review resumes at the approval. Steps that may run again are idempotent (the trace is rewritten
  whole, proposals are found by origin, applying an approval is the atomic `agents.decide`), because LangGraph runs an
  interrupted step again from its start. The checkpoint thread id is generated by the platform and found only through
  the run inside the tenant's session.
- **Stale evidence voids the work**: if the claim's evidence changed while the agents read it, the run proposes
  nothing; if it changes while a person reviews, the approval is refused when applied.
- **A baseline**: `mode="single"` skips the verifier. The rules alone, one agent and the pair are compared on cases
  written independently of the generator before the pair is claimed to help.

## Consequences
- An agent can make the review faster (a cited reading of the passage that matters, a proposal one click from done)
  and cannot make a claim pass: the worst it can do is propose something a person declines, or send a question.
- A small local model will often finish without findings or with citations that fail; the cost is review time, and
  the comparison measures it.

## Alternatives considered
- *One agent with a "verify your answer" step.* The same context checks itself; a second context that sees only the
  claims is a stronger check for the same tokens.
- *Agents that write verdicts directly, with an approval prompt.* The approval would be in the agent's loop; here the
  domain service applies it, against the evidence, in its own transaction.
- *An explicit state machine instead of LangGraph.* Equivalent guarantees are possible; LangGraph gives checkpoints,
  interrupts and resumption that are already tested, at the cost of re-executing an interrupted step, which the design
  makes harmless.
